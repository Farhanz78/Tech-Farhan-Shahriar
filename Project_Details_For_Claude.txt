6. HOW A GAME IS SERVED  (the part that is easy to get wrong)
----------------------------------------------------
Supabase Storage rewrites text/html to text/plain on every response,
unconditionally. Pointing an iframe at a stored index.html shows source code as
text instead of running the game. No bucket setting changes this.

So:
  - app/g/[id]/route.ts serves the entry HTML from THIS origin as real
    text/html and injects <base href="...storage.../"> so relative asset paths
    resolve back to Supabase Storage.
  - Every other file (js, wasm, textures, audio) streams direct from the Storage
    CDN. Only a few KB of HTML passes through the server.
  - app/play/[id]/page.tsx renders components/GameFrame.tsx, which iframes
    /g/[id].

Both 'inline' and 'bundle' rows go through /g/[id]. Inline rows no longer use a
blob: URL, because a blob: URL inherits the creating page's origin, which let
game code read the admin's Supabase session out of localStorage.

The iframe keeps allow-same-origin deliberately: that is what gives a game
working localStorage and IndexedDB for save data. Removing it gives the frame an
opaque origin and most WebGL builds then fail during startup. Origin isolation
is done with NEXT_PUBLIC_GAME_ORIGIN instead.

There is no "anti-theft" script any more. The old one blocked right-click and
F12; it protected nothing (view-source, the network tab and browser menus are
untouched by it), it broke games that use right-click as an input, and it hid
the game's own error output. Do not add it back.


7. UPLOAD PIPELINE  (lib/game-upload/)
----------------------------------------------------
  read-zip.ts   fflate, dynamically imported so the Node build never enters the
                server bundle
  normalize.ts  backslash->slash (Windows "Compressed folder" writes backslash
                entry names), junk + path-traversal filtering, wrapper-folder
                peeling, entry-point detection
  mime.ts       extension -> MIME. REQUIRED: supabase-js silently ignores the
                contentType option when the body is a Blob or File and uses
                blob.type instead. Wrong MIME breaks CSS silently, blocks ES
                modules, and breaks WebAssembly.instantiateStreaming.
  upload.ts     5-way concurrency, retry with backoff, progress, cleanup

Blocked at upload time, with an explanation shown to the user:
  - .gz / .br pre-compressed builds (Content-Encoding cannot be set on Supabase
    Storage, so the browser never decodes them)
  - any single file over 50 MB
